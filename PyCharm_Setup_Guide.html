Setting up the DDOT GIS project in PyCharm Professional

How to clone, configure, run and test the DDOT Maintenance Operations GIS project (permits, service requests and roadway subblocks) in PyCharm Pro on Windows, WSL Ubuntu and macOS on Apple Silicon (M4 Max).

Repo: fultonq/Fulton_Q_Shannon_GIS Branch: v2.3-data-review QGIS 3.40 / 3.44 LTR Python 3.12+

How the project fits together

The project uses two Python interpreters, because PyQGIS can only be imported by the Python that ships with QGIS:

InterpreterRunsPackages
Project venv (.venv) 01_pull_and_process_data.py, generate_and_launch_gis.py, the tests requirements-dev.txt: geopandas, pandas, pyogrio, pyproj, requests, shapely, pytest
QGIS Python 02_create_qgis_project.py: exports the shapefiles and builds both .qgz projects Comes with QGIS (PyQGIS); nothing to install

1 · 01_pull_and_process_data.py

Pulls the three DC GIS REST layers, snaps permits, enriches subblocks, and writes data/ddot_maintenance_operations.gpkg, the log and the summary report. Needs internet.

2 · 02_create_qgis_project.py

Writes shapefiles/, ddot_maintenance_operations.qgz and shapefiles_map.qgz, validates them and (optionally) zips the deliverable.

Runner · generate_and_launch_gis.py

Runs 01 then 02 into build/<Name>_GIS_V2/, packages the zip and opens QGIS. Finds the QGIS Python itself (or via QGIS_PYTHON).

Tests · tests/

pytest. The network marker hits the live services; deselect it with -m "not network" for a fast offline run (57 tests).

Platform setup

Install the prerequisites

  • PyCharm Professional, via JetBrains Toolbox or the standalone installer.
  • Git for Windows (git --version in PowerShell to check).
  • Python 3.12 or 3.13 from python.org (tick Add python.exe to PATH). The Microsoft Store Python also works.
  • QGIS LTR. Either the OSGeo4W network installer (this machine: per-user at %LOCALAPPDATA%\Programs\OSGeo4W, QGIS 3.44 LTR) or the standalone MSI (C:\Program Files\QGIS 3.44.x).

Where to clone: use a plain local folder such as C:\dev, not OneDrive. OneDrive syncing a .venv and a live GeoPackage causes slowdowns and file locks.

Connect GitHub over SSH (once per machine)

ssh-keygen -t ed25519 -C "you@example.com"
type $env:USERPROFILE\.ssh\id_ed25519.pub   # copy into GitHub ▸ Settings ▸ SSH and GPG keys
ssh -T git@github.com                       # "Hi fultonq! You've successfully authenticated"

Or skip SSH and sign in with Settings ▸ Version Control ▸ GitHub ▸ + and clone the HTTPS URL.

Clone and check out the branch

  1. PyCharm welcome screen ▸ Clone Repository.
  2. URL git@github.com:fultonq/Fulton_Q_Shannon_GIS.git, directory C:\dev\Fulton_Q_Shannon_GIS ▸ Clone. Trust the project when asked.
  3. Git ▸ Branches… ▸ origin/v2.3-data-review ▸ Checkout.

Create the project venv

  1. Click the interpreter widget in the bottom-right status bar ▸ Add New Interpreter ▸ Add Local Interpreter…
  2. Virtualenv ▸ Generate new, location C:\dev\Fulton_Q_Shannon_GIS\.venv, base interpreter your Python 3.12/3.13 ▸ OK.
  3. Open the Terminal tool window (it activates the venv) and install:
python -m pip install --upgrade pip
pip install -r requirements-dev.txt

Windows wheels for geopandas, pyogrio, shapely and pyproj bundle GDAL/GEOS/PROJ, so no separate GDAL install is needed.

Register the QGIS Python (for 02)

The OSGeo4W Python only imports qgis.core when its environment variables are set. There are two ways to give it that environment.

Option A: Shell Script run configuration (simplest). Run ▸ Edit Configurations ▸ + ▸ Shell Script:

FieldValue
Name02 Build QGIS projects
ExecuteScript text
Script text& "$env:LOCALAPPDATA\Programs\OSGeo4W\bin\python-qgis-ltr.bat" 02_create_qgis_project.py --no-package
Working directory$ProjectFileDir$
Interpreter pathpowershell.exe

With the standalone MSI, use "C:\Program Files\QGIS 3.44.x\bin\python-qgis-ltr.bat" instead.

Option B: a real interpreter, so you can use breakpoints and PyQGIS code completion.

  1. Add New Interpreter ▸ Add Local Interpreter… ▸ System Interpreter ▸ %LOCALAPPDATA%\Programs\OSGeo4W\bin\python.exe. Name it QGIS Python.
  2. In the 02 Python run configuration (next section), paste these into Environment variables. Replace R with your OSGeo4W folder, e.g. C:\Users\fqsha\AppData\Local\Programs\OSGeo4W:
PATH=R\bin;R\apps\qgis-ltr\bin;R\apps\Qt5\bin;R\apps\Python312\Scripts;C:\Windows\system32;C:\Windows
PYTHONHOME=R\apps\Python312
PYTHONPATH=R\apps\qgis-ltr\python
QGIS_PREFIX_PATH=R\apps\qgis-ltr
QT_PLUGIN_PATH=R\apps\qgis-ltr\qtplugins;R\apps\Qt5\plugins
GDAL_DATA=R\apps\gdal\share\gdal
GDAL_DRIVER_PATH=R\apps\gdal\lib\gdalplugins
PROJ_DATA=R\share\proj
PYTHONUTF8=1

Tested on this machine: with exactly these variables, OSGeo4W's python.exe loads QGIS 3.44.15, resolves EPSG:2248 and imports geopandas.

Set these per run configuration, never system-wide, and don't launch PyCharm from an OSGeo4W shell. PYTHONHOME pointing at QGIS's Python 3.12 breaks every other interpreter, including your venv.

Tell the runner where QGIS is

generate_and_launch_gis.py looks for QGIS in C:\Program Files\QGIS* and C:\OSGeo4W*. A per-user OSGeo4W install isn't in either place, so add this to the runner's run configuration environment:

QGIS_PYTHON=C:\Users\fqsha\AppData\Local\Programs\OSGeo4W\bin\python-qgis-ltr.bat

Open results in QGIS

& "$env:LOCALAPPDATA\Programs\OSGeo4W\bin\qgis-ltr.bat" shapefiles_map.qgz

Or double-click the .qgz in Explorer.

Model: PyCharm Pro runs on Windows. The code, venv and QGIS live inside Ubuntu, and PyCharm runs everything there through its WSL interpreter support. QGIS's GUI opens on your Windows desktop through WSLg.

Prepare Ubuntu

sudo apt update
sudo apt install -y git python3-venv python3-pip
# QGIS LTR + PyQGIS: follow qgis.org ▸ Download ▸ Linux ▸ Debian/Ubuntu (LTR repository), then
sudo apt install -y qgis python3-qgis
python3 -c "import qgis.core; print('PyQGIS OK')"

This machine: Python 3.13, QGIS 3.40.8 at /usr/bin/qgis.

Clone inside the Linux file system

mkdir -p ~/qgis_project02 && cd ~/qgis_project02
git clone git@github.com:fultonq/Fulton_Q_Shannon_GIS.git python_qgis
cd python_qgis && git checkout v2.3-data-review

Keep the clone under ~. Working from /mnt/c/... is very slow, and GeoPackage locking misbehaves there.

SSH keys in Ubuntu are separate from Windows: run ssh-keygen -t ed25519 in Ubuntu and add ~/.ssh/id_ed25519.pub to GitHub.

Create the venv (in Ubuntu)

python3 -m venv .venv
.venv/bin/pip install --upgrade pip
.venv/bin/pip install -r requirements-dev.txt

Open the project in PyCharm

Recommended: File ▸ Open… ▸ \\wsl.localhost\Ubuntu-24.04\home\fqsha\qgis_project02\python_qgis. PyCharm Pro detects the WSL location and uses Git from inside Ubuntu.

Faster on large projects: welcome screen ▸ Remote Development ▸ WSL ▸ pick Ubuntu-24.04 and the folder. The IDE backend then runs inside Linux, so indexing isn't slowed down by the share.

Add both interpreters

  1. Interpreter widget ▸ Add New Interpreter ▸ On WSL… ▸ distribution Ubuntu-24.04 ▸ Virtualenv ▸ Select existing ▸ /home/fqsha/qgis_project02/python_qgis/.venv/bin/python. Make this the project interpreter.
  2. Again On WSL… ▸ System Interpreter ▸ /usr/bin/python3. Name it QGIS Python (WSL). No extra environment is needed; 02 sets QT_QPA_PLATFORM=offscreen itself.

The runner finds /usr/bin/python3 automatically, so QGIS_PYTHON isn't needed here.

Open results in QGIS

Linux QGIS (WSLg window):

qgis shapefiles_map.qgz &

Windows QGIS: copy the folder to the Windows drive first. Windows QGIS cannot open the GeoPackage over \\wsl.localhost (database is locked):

rsync -a --exclude='.venv/' --exclude='__pycache__/' --exclude='.pytest_cache/' --exclude='build/' \
  ./ /mnt/c/Users/fqsha/OneDrive/Desktop/python_qgis/

The macOS steps follow the standard Apple Silicon toolchain but have not been run on a Mac for this project. The QGIS Python path in step 4 is the one to check first.

Find and register the QGIS Python

ls /Applications/QGIS*.app/Contents/MacOS/bin/python3
/Applications/QGIS-LTR.app/Contents/MacOS/bin/python3 -c "import qgis.core; print('PyQGIS OK')"

If that path doesn't exist in your QGIS build, locate the bundled interpreter:

find /Applications/QGIS-LTR.app/Contents -maxdepth 3 -name 'python3*' -type f -perm -u+x
  1. PyCharm: Add Local Interpreter… ▸ System Interpreter ▸ that path. Name it QGIS Python (macOS).
  2. If import qgis.core fails from PyCharm but works in Terminal, add PYTHONPATH=/Applications/QGIS-LTR.app/Contents/Resources/python to the 02 run configuration.
  3. The runner looks for /Applications/QGIS*.app/Contents/MacOS/bin/python3. If yours is elsewhere, set QGIS_PYTHON=<path> in the runner's run configuration.

Open results in QGIS

open -a QGIS-LTR shapefiles_map.qgz

Arial ships with macOS, so the street labels render as designed.

Run configurations

Typical cycle: 01 (refresh data) → 02 (shapefiles + projects) → open shapefiles_map.qgz in QGIS → Tests → commit.

Running the tests

  1. Settings ▸ Tools ▸ Python Integrated Tools ▸ Default test runner: pytest.
  2. Run ▸ Edit Configurations ▸ + ▸ Python tests ▸ pytest: target Custom / script path tests, additional arguments -m "not network", interpreter Project venv.
  3. Expected: 57 passed, 1 deselected. Drop -m "not network" to include the live-service test.

Or from the PyCharm terminal:

python -m pytest -q -m "not network"

Troubleshooting

SymptomCause / fix
PyQGIS is not importable from this interpreter02 ran with the venv. Switch its run configuration to the QGIS Python (Windows: Option A or B).
Runner: Could not find a Python interpreter with PyQGISSet QGIS_PYTHON (or pass --qgis-python) to python-qgis-ltr.bat / /usr/bin/python3 / the QGIS.app python3.
Windows: ImportError: DLL load failed for qgisAn environment variable is missing or R is wrong in Option B. Compare with OSGeo4W\bin\o4w_env.bat and etc\ini\*.bat.
Venv suddenly can't start (No module named 'encodings')PYTHONHOME leaked from the QGIS environment into the venv's run. Keep the QGIS variables inside the 02 run configuration only.
Windows QGIS: many layers unavailable, database is lockedProject opened from \\wsl.localhost\.... Open the copy on the Windows drive.
QGIS warns that a font is missingRebuild with 02 v2.6.1 or later; labels use Arial, and validation rejects any other label font.
Indexing very slow on the WSL projectUse Remote Development ▸ WSL, or exclude .venv, build and data (right-click ▸ Mark Directory as ▸ Excluded).
macOS: “QGIS-LTR can't be opened”Gatekeeper. Finder ▸ right-click the app ▸ Open once.
Step 01 times outThe DC GIS services are slow or down. Re-run with --timeout 120 --retries 8.
